# Data provenance

## PanTHERIA traits

`raw/PanTHERIA_1-0_WR05_Aug2008.txt` is the committed WR05 PanTHERIA source
file from Jones et al. (2009), *PanTHERIA: a species-level database of life
history, ecology, and geography of extant and recently extinct mammals*.
The publication and downloadable data are available from the Ecological
Archives at <https://esapubs.org/archive/ecol/E090/184/>.

`raw/species_traits.csv` is a normalized extract generated by
`scripts/build_traits.py`. It contains body-mass traits for all species in
the census summary, while the three active candidate species are wildebeest,
waterbuck, and kudu. Zebra is temporarily excluded from forecasting because
PanTHERIA lacks required reproductive traits. The script is
re-runnable when the source file is deliberately refreshed.

PanTHERIA encodes unavailable values as `-999`. The builder converts those
to empty CSV fields, which load as missing values. Units are normalized as
follows:

- Adult mass: grams to kilograms
- Gestation: days to months using 30.44 days per month
- Maximum longevity: months to years
- Sexual maturity: days to years

PanTHERIA supplies one sexual maturity age rather than separate male and
female ages. The normalized table copies that value into both model columns
as an explicit interim assumption. The `male_ratio`, juvenile mortality,
and carrying-capacity fields remain empty until supported by a suitable
source.

Zebra has no PanTHERIA values for gestation, interbirth interval, or sexual
maturity. It must not be forecast with the normalized table until those
parameters are sourced elsewhere.

## Population counts

The first source file is `raw/KNPCountsSummary.txt`, downloaded from the
public DataONE REST object endpoint:

`https://cn.dataone.org/cn/v2/resolve/judithk.815.1`

It is the data object attached to the SANParks record
`judithk.814.4`, *Census totals for large herbivores in the Kruger National
Park summarized by year and region 1965-1997* (SANParks, 2007). The raw
object has MD5 checksum `48938704ad3613b903e6093b9c69a6fa`.

The file is tabular text with year, species, regional counts, and a `TOTAL`
column. The normalized extract includes all census species so their body
masses can contribute to the community biomass proxy. The
downloaded file is retained unchanged as provenance evidence; it still needs
to be normalized into the model's counts schema. Missing regional cells and
years with incomplete coverage must not automatically be interpreted as
zero. The total-count series must remain limited to 1965-1997 because the
survey methodology changed in 1998.

There is intentionally no automated counts builder. Once the raw data has
been reviewed and normalized, each model count row should retain a source
citation and survey-method field. Census totals do not contain an
adult/juvenile split, so that split must be seeded separately from a
documented stable-stage assumption.

For the current plumbing pass, the model uses a provisional 50% juvenile
fraction, giving an assumed 50/50 adult/juvenile split for every reported
total. This is a temporary modelling assumption and must be replaced or
sensitivity-tested when a literature-based stage proportion is selected.

`scripts/tune_assumptions.py` evaluates a small grid of juvenile fractions
and male ratios against the reported totals. Its output is diagnostic only;
the best numerical fit is not automatically a biologically valid parameter.

`scripts/evaluate_model.py` reports backtest accuracy for the forecastable
species. It uses only rows with reported totals and provides MAE, RMSE, MAPE,
normalized MAE, and signed bias. The 1965 starting row is an initialization
point, so it will have zero error by construction and should not be treated
as an independent accuracy result.

`raw/species_counts.csv` is the normalized candidate-species extract produced
by `scripts/parse_counts.py`. It keeps rows whose reported total is missing
so those gaps remain visible for review; blank totals are not treated as
zero. The parser adds the DataONE record, object identifier, source URL, and
survey method to every row. It does not create adult or juvenile counts.
